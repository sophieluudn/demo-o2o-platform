# O2O 後台 Demo

依據提供的後台截圖製作，使用 Vite + JavaScript / CSS，搭配 Vue 3 與 Element Plus 元件。純前端，沒有串接真實身分驗證或後端 API。會員資料均為示範資料。

## 本機開發

需要 Node.js 22 或更新版本。用 VS Code 開啟此資料夾，在終端機執行：

```sh
npm install
npm run dev
```

開啟終端機顯示的網址。修改程式後瀏覽器會即時更新。

## 頁面與操作

- 首頁：深藍底登入畫面，點擊「登入」即視為通過身分檢查，先顯示單位選單，選擇單位後才進入後台首頁。選單使用單位管理中的啟用單位；未登入會返回登入頁，尚未選擇單位會返回單位選單。登入狀態及選擇的單位保存在目前分頁的 `sessionStorage`，不是正式 Google OAuth 登入。
- 專案列表：單位下拉篩選（預設進入單位）搭配名稱／單位搜尋、筆數切換、編號排序、新增、編輯、複製網址；重設會清除文字及單位條件。
- 全站主要列表共用專案列表的分頁樣式：專案、使用者、角色、單位、會員使用紀錄及登入／註冊統計皆支援每頁 10／20／50 筆、前後頁、頁碼與跳頁；重新查詢會回到第一頁。
- 新增／編輯：基本資料、圖片預覽、富文字、問卷題目、追蹤碼、備註，確定送出後存至 localStorage。
- QRCode & URL：產生可掃描的 QRCode，下載 PNG 或複製網址；目的頁是本 demo 的活動說明頁。
- 會員使用記錄：日期／會員搜尋、展開明細、匯出 CSV、查看本次開啟期間的最近匯出時間。
- 登入與註冊統計：固定示範統計、分頁與 CSV 匯出。查詢按鈕只驗證日期，不計算真實資料。
- 側邊選單收合與全螢幕切換。

各專案共用示範會員記錄；服務與電子報選單、問卷編輯器是操作示範，沒有串接外部系統。上傳圖片存在目前瀏覽器，建議壓縮後使用。清除網站 localStorage 可還原初始資料。不同裝置／瀏覽器不會同步。

## 放上 GitHub

建立空白 GitHub repository，將此資料夾內容放到 repository 根目錄（package.json 與 .github 直接位於根目錄）。

```sh
git init
git add .
git commit -m "Create O2O admin demo"
git branch -M main
git remote add origin https://github.com/YOUR-NAME/YOUR-REPO.git
git push -u origin main
```

在 GitHub repository 的 **Settings → Pages → Build and deployment → Source** 選 **GitHub Actions**。本專案已附部署 workflow；推送 main 後會建置並部署。部署網址由 Actions 的 deploy 工作顯示。若尚未設定 Pages，可在設定後由 Actions 手動執行 Deploy demo to GitHub Pages。

Hash 路由與相對 base 適用 repository 子路徑，不需伺服器 rewrite。

## 經常修改的檔案

- `src/main.js`：頁面內容、示範資料、按鈕行為、表單欄位。
- `src/style.css`：側欄、顏色、表格、表單間距與手機版樣式。
- `index.html`：網站標題、語言及描述。
- `.github/workflows/deploy.yml`：GitHub Pages 部署。

給 Codex 的提示範例：「請修改 src/style.css，將專案列表欄高改成 60px，保持其他頁面不變。」

## 正式建置

```sh
npm run build
npm run preview
```

`dist/` 是部署產物，不需手動修改或提交。QRCode 使用 qrcode，圖示使用 Lucide。沒有使用遠端 CDN 或外部資料 API。

## 系統管理（本機示範）

- 使用者管理：依單位、狀態、姓名或 Email 篩選；點擊姓名編輯。表單包含狀態、姓名、Email 與「單位與角色」，支援多組指派及欄位警告。
- 跨單位設定保存在使用者的 `assignments` 陣列，列表與單位篩選涵蓋全部設定。舊使用者的單位／角色會轉為第一組設定，並保留第一組的 `unit`／`role` 舊欄位及其他原始欄位。最後一位啟用管理員的保護會檢查全部角色設定。
- 每個使用者在同一單位只能設定一個角色；新增及編輯儲存時皆檢查重複單位。角色下拉只顯示所選單位的角色，更換單位會清除原角色；儲存時也會檢查角色所屬單位。舊資料若有重複或跨單位錯配，不自動合併或改配角色，需在編輯時修正後才能儲存。
- 新增使用者第一組單位預設為目前查詢的啟用單位，篩選全部時採本次進入單位。舊使用者若無指派陣列，保留舊單位／角色轉換；明確的空陣列不會補回授權。
- 角色管理：依單位、狀態與角色名稱篩選，點擊角色名稱編輯狀態、單位、角色名稱、說明及功能權限。權限依目前後台選單分組；內建管理員保持啟用及完整權限。舊角色自動補上單位、說明與啟用狀態。
- 各單位的角色獨立：不同單位可建立同名角色，同一單位內名稱不可重複。一般角色僅屬於個別單位；內建管理員固定屬於全部單位、啟用及完整權限，只可修改名稱與說明。已指派的一般角色不可任意移動單位；舊的失效全域角色可由有權者修正。
- 單位管理：沿用 `#system/projects` 路由，顯示編號、名稱與狀態，支援篩選、新增及編輯；更名同步更新 `o2o-projects` 專案及 `o2o-system` 的使用者、角色與指派。
- 選單管理已移除，系統管理固定顯示使用者、角色及單位管理。舊資料的選單設定與 `menus` 權限會在讀取時清除，其他管理資料保留。
- 使用者、角色與單位保存在 `o2o-system`。未建立真實帳號、密碼、登入或後端權限檢查；狀態與權限皆為本機示範設定，專案、使用者與角色列表依進入單位篩選，僅系統管理員可選全部單位。權限原則與待補強事項見 [權限 review](docs/PERMISSIONS_REVIEW.md)。


## 從 VS Code 直接預覽 index.html

以瀏覽器開啟根目錄的 index.html，或使用 VS Code 的 Live Server 預覽。請保留 preview 資料夾，無須先啟動 Vite。

修改原始碼後執行 npm run build:preview 更新預覽檔；npm run build 會同步產生 dist 與 preview。開發時仍可執行 npm run dev。

登入畫面提供 Email 輸入以模擬 Google 登入後取得的帳號，預填內建管理員 Email；沒有 Google OAuth，也不驗證帳號持有權。正式環境需要 Google OAuth Client ID 及後端身分驗證。

- Email 去除首尾空白、忽略大小寫後必須唯一；新增或修改為既有 Email 會警告並阻擋儲存，請編輯既有使用者增加指派。登入帳號未建檔、停用、重複或沒有有效單位／角色時顯示錯誤。
- 一般使用者選 A 後列表只顯示 A，下拉只有 A；切換 B 後依 B 的角色判斷。系統管理員預設進入單位，可選全部單位。
- 使用者列表在個別單位篩選時仍包含全域系統管理員，該列顯示「全部單位」及內建角色目前的名稱。停用管理員使用者需先確認「使用者為系統管理員，確定要停用?」，取消不儲存；最後一位管理員仍不可停用。內建管理員角色可編輯名稱／說明，角色本身不可停用。
- 角色列表的單位篩選同樣保留內建系統管理員角色，顯示所屬「全部單位」；一般角色仍依單位篩選，顯示內建角色不會額外授予編輯權限。
- 「單位與角色」提供「全部單位」（`*`）及啟用個別單位。全部單位只可指派內建系統管理員，個別單位只可指派該單位啟用一般角色。全域指派必須是唯一一列；操作與儲存皆檢查互斥及單位重複。停用項目不供新增指派。
- 有使用者編輯權限者可修改可見使用者的姓名、Email、整體狀態及其他單位指派；不新增權限層級限制。內建管理員依角色 ID 1 識別，名稱可改，所屬範圍不可改，不提供任何角色刪除。
- 單位依角色功能權限管理；名稱忽略英文大小寫檢查重複。更名同步專案、使用者、角色及指派，分別寫入 `o2o-projects`／`o2o-system`。
- 選單、列表、直接網址、操作按鈕、儲存、匯出及匯出紀錄均依角色判斷；紀錄按使用者、專案、報表區分。新增專案歸屬登入後選擇的單位。
- C 帳號選單提供「切換專案」與「登出」。重新整理、路由切換、操作及跨分頁更新會重查權限；使用者停用或全部指派失效會登出，目前單位失效但仍有其他指派則返回單位選單。
- 單位管理資格與業務存取分開：只要使用者及對應管理角色仍啟用且匹配，有檢視權者仍可看有權管理的停用單位，有編輯權者可重新啟用；停用單位不開放專案等業務功能。管理者須仍有其他有效單位可登入。
- 停用設定儲存後立即重查，必要時關閉編輯視窗、清除目前專案／報表狀態並返回選單或登出。重新登入不會恢復停用指派。
- 舊管理員個別單位指派轉為唯一「全部單位＋內建管理員」，不清空其他使用者、角色、單位或專案；一般角色的舊全部單位設定保留但標示失效，不自動擴大授權。

以上為純前端示範，正式授權須由後端執行。完整規則見 [權限規格](docs/PERMISSIONS_REVIEW.md)。

權限測試：啟動開發伺服器後，在已安裝 Playwright 及 Microsoft Edge 的環境執行 `node scripts/verify-access.mjs`；可用 `O2O_TEST_URL` 指定測試網址。
